# Minecraft RPG/PvEサーバー向け作曲ルールブック

## 技術ルール：ノートブロックの制約を前提に書く

このジャンルの音は「制約の使い方」で決まります。DAWで普通に書いてから移植するのではなく、最初からNBS上の制約内で考えるのが再現の近道です。

| 項目       | 制約                                                                                                                                                           | 作曲上の対処                                                                                      |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 音域       | 1楽器あたり2オクターブ（25音、F#〜F#）                                                                                                                         | 楽器ごとの音域を役割分担に使う。旋律はハープ/フルート、低音はベース、高音装飾はベル/チャイム/ゼナ |
| 楽器       | バニラ16種（ハープ、ベース、スネア、ハット、バスドラム、ベル、フルート、チャイム、ギター、木琴、鉄琴、カウベル、ディジュリドゥ、ビット、バンジョー、プリング） | 1曲で使う楽器を絞り、地域ごとに「主役楽器」を決める                                               |
| 音の長さ   | すべて減衰音。持続音が出ない                                                                                                                                   | 同音を細かく連打する、アルペジオで和音を伸ばす、薄く重ねて残響風にする                            |
| 音量・定位 | NBSではレイヤーごとに音量・パン設定が可能                                                                                                                      | 伴奏を小さく、旋律を大きく。左右に振ってオーケストラ風の広がりを出す                              |
| テンポ     | サーバーは20tick/秒で再生                                                                                                                                      | 20、10、6.67、5 tick/秒など、20を割り切れる値に合わせると揺れにくい                               |
| 負荷       | 同時発音が多いと重い・聞き取りにくい                                                                                                                           | 1拍あたりの同時音数を抑え、レイヤーを役割で整理する                                               |

音域外の音が欲しい時は、オクターブ移調するか、別の楽器に旋律を受け渡すのが定番です。「制約で鳴らせない音を、別の楽器で補う」発想がオーケストレーションそのものになります。

## 用途別の設計ルール：曲は「場所」と「状況」に紐づく

曲はすべて、特定の地域・クエスト・ボス・イベントに割り当てます。
まず用途を決め、長さと役割を合わせるのが基本です。

| 用途                 | 実例の長さ   | 役割                            | 書き方のルール                                                             |
| -------------------- | ------------ | ------------------------------- | -------------------------------------------------------------------------- |
| 地域曲（町）         | 約1:30〜5:00 | 住人・文化・産業の性格を描く    | 主役楽器と旋法で文化を表現。長く聴いても疲れない密度に                     |
| 地域曲（フィールド） | 約2:30〜7:00 | 探索中のBGM。何度もループされる | 起伏はゆるやかに。静かな区間を入れ、ループ継ぎ目を自然に                   |
| クエスト曲           | 約0:50〜5:00 | 物語の一場面を演出              | そのクエストの主題を前面に。短い場面は短く切る                             |
| ボス・ミニゲーム     | 約2:00〜5:40 | 緊張感と高揚                    | テンポ速め、打楽器を厚く。フェーズごとに別曲や別セクションを用意           |
| ダンジョン・レイド   | 数分の長尺   | 攻略中の持続的な緊張            | フェーズ構成に合わせて展開を設計                                           |
| ジングル             | 約4〜11秒    | 開始・成功・失敗の通知          | 成功は長調で上行、失敗は短調・下行やおどけた終わり方。一瞬で判別できること |

ポイントは「曲がゲームの状態を伝えるUIでもある」ことです。プレイヤーは音だけで、今どこにいてどんな状況かを判断できるように作られています。

## 作曲手法の共通点：モチーフで世界をつなぐ

最も再現すべき共通点は、曲同士をモチーフで結び、サウンドトラック全体を一つの物語にすること。
各曲がどの曲の旋律を引用しているかは都度記載する。

**1. モチーフの引用で地域と物語をつなぐ**

- 地方の代表曲を「地方テーマ」にする
- 物語上の関係を旋律で示す
- 古い地方の曲を新地方で鳴らす
- 英雄・敵・勢力のテーマ

**2. 曲とロアを一体で設計する**

- 各曲に主人公の日記風「ログ」が付き、その場所の印象を一人称で語っている。
- 曲名は情景や感情を表す短い英語フレーズ

**3. 構成とループ**

- 地域曲は数分の長さで、イントロ→主題→展開→主題回帰→ループ、という形が基本（各曲の長さからの推定）。
- ボス・ダンジョン曲はゲームのフェーズと連動させる。段階ごとに別曲があるなど、

## 再現用ワークフローとチェックリスト

1. **楽器を割り振る**：主役楽器1〜2種、伴奏、低音、打楽器、装飾。楽器ごとの2オクターブに収まるか確認する。
2. **テンポを決める**：20を割り切れる tick/秒 にする。戦闘は速め、町・フィールドは遅め。
3. **構成を組む**：イントロ→主題→展開→主題回帰→ループ。ボス・レイドはフェーズごとに区切る。
4. **持続音を作る**：連打、アルペジオ、薄い重ねで減衰音の弱点を補う。
5. **サーバーで鳴らして調整する**：実際のゲーム内で、戦闘音や環境音の中でも旋律が聞こえるか、ループの継ぎ目が自然かを確認する。(手動で行います。)

**完成前チェック**

- [ ] 用途に合った長さになっている
- [ ] 主題を数小節聴いただけで場所・状況がわかる
- [ ] 既存のモチーフとの関係（引用・変奏）を記録した
- [ ] すべての音が各楽器の音域内にある
- [ ] テンポが 20 tick/秒 を割り切れる値になっている
- [ ] 同時発音が多すぎない
- [ ] ループしても違和感がない
- [ ] ログと曲名が付いている
