# アイテムの yaml の更新を、ゲーム内のアイテムへ反映する (item patch)

アイテムの yaml (items/*.yml) が変わると、それまでに作られたアイテム (名前・説明文・見た目は作った時点のもの) を、新しい内容で作り直す。プレイヤーが拾い直す必要はない。

## しくみ
- **指紋 (fingerprint)**: 読み直しのたびに、各アイテムの定義から「素のアイテム」を作り、その中身のハッシュを取る。名前・説明文・素材・見た目・スキルの説明・クラスの印など、表示に効くものはすべて入る。
- **アイテムの印**: アイテム1個ごとに、作ったときの指紋を持たせる (PDC `iruurpg:item_rev`)。今の指紋と違うアイテムだけを見る。作り直した結果が、元のアイテムに印を足しただけと同じなら (印のない既存のアイテムで、yaml が変わっていないもの)、**印だけ付けて、ほかには触らない**。違うときだけ作り直す。新しく作るアイテムには、作った時点で今の指紋が付く (確認済みのアイテムとスタックできるように)。
- **止める**: config の `item-patch.enabled: false` で、作り直しも印付けもしない (新しく作るアイテムにも印を付けない。アイテムはそのまま)。true に戻すと、次の読み直し・ログインで確認する。
- **失敗**: 作り直しで例外が出たアイテムは、元のまま残し、ログにアイテムの id を出す。指紋が作れない定義 (素材が AIR・アイテムでないブロック、作るときの例外) は、ログに出して飛ばし、そのアイテムは直さない (ほかの定義は続ける)。
- **プラグインは止めない**: 確認の全体 (起動時・読み直し時) で例外が出ても、プラグインの起動・読み直しは続く。アイテムの更新だけが、次の読み直しまで止まる (ログに SEVERE)。
- **版**: 前回から指紋が変わった定義があると、全体の版 (整数) が 1 上がる。版と指紋は `plugins/iruuRPG/item-patch.yml` に保存する。プレイヤーは確認済みの版を持つ (プレイヤーの PDC `iruurpg:item_patch_version`)。

## いつ・どこを直すか
| いつ | どこ |
|---|---|
| yaml の読み直しで版が上がったとき (その場で) | マーケット (出品・買い注文・返却箱)、読み込み済みの個人倉庫 (開いている画面も)、オンラインのプレイヤー (インベントリ・防具・オフハンド・カーソル・エンダーチェスト・開いているチェスト類) |
| ログインしたとき (版ごとに1回) | そのプレイヤーの上と同じ場所。読み直しのときにその場で直したプレイヤーも、次のログインでもう一度確認する (不具合対策) |
| 個人倉庫をファイルから読んだとき | その倉庫 (直したら保存) |
| 置かれたチェスト・樽・シュルカーボックスなどを開いたとき | その中身 |

直さないもの: 額縁・地面に落ちているアイテム・シュルカーボックス (アイテム) の中身。これらはインベントリや開いた入れ物に入ったときに直る。定義が消えたアイテムは、そのまま残す。

## 残すもの (固有の情報)
作り直しても、次のものはすべて残す。
- PDC のすべてのキー (クラフトの強化 `bonus_stats`・属性の強化 `bonus_elements`、そのほか、ほかの機能が付けたキー)
- クラフト品のレア度 (PDC `iruurpg:rarity`。印のない古いクラフト品は、名前の `[**]` から読み、読めなければ強化の数から計算して、保存する)
- 個数
- エンチャント (定義の光沢 = LUCK は、定義に従う)

クラフト品は、作り直しても「クラフト品」の欄 (強化の一覧) が説明文に残る。

## 通知・ログ
- 作り直したアイテム (見た目が変わったもの) があったときだけ、チャットに1行 (「[アイテム] N 個のアイテムを、最新の内容に更新した。」)。印だけ付けたものは知らせない。
- サーバーのログ: 変わった定義の id、そして数 (`rebuilt` 作り直した / `stamped only` 印だけ / `failed` 失敗して元のまま / `crafted rarity not readable` 名前の [**] が読めず、強化の数からレア度を出したクラフト品)。読み直しのときは、マーケット・倉庫の分と、オンラインのプレイヤーの分を1行ずつ。ログイン・倉庫の読み込み・チェストは、何かあったときだけ1行。

## テスト
- `./gradlew itemPatchTest`: `src/test/.../item/ItemPatcherTest` (tag `server`)。dev bundle のサーバーの本物のアイテム・PDC の処理で動く。変わったアイテムだけが作り直されること、中身が同じなら印だけ付くこと (新しいアイテムとスタックできる)、クラフトの強化・属性・レア度・ほかのキー・エンチャント・個数が残ること、古いクラフト品のレア度を名前から読むこと (読めない数を数える)、失敗したら元のまま残ること、止めたら何もしないこと、版が変わったときだけ上がり再起動のあとも保たれること。
- `./gradlew itemPatchTest -PitemPatchData=<plugins/iruuRPG の写し、または yml リポジトリ>`: 上に加えて、サーバーの本物のアイテム (items/・iskill/・skills/) すべてで、指紋が作れること・作ったアイテムが最新と判定されること・印のない既存のアイテムが「印だけ」になる (作り直し 0) ことを確かめる (`ItemPatchRealDataTest`。フォルダを渡さないと飛ばす)。起動に関わる変更のあとは、これを通してから反映する。
- `./gradlew test` (`build` に含まれる) は軽いものだけ (`ItemPatcherNameTest`: 名前の印の読み取り)。サーバーを起動するテストは `build` では動かない。

## 武器・防具をスタックさせない (移行)
- 武器と防具 (`RpgItemDefinition.unstackable()`) は、作るときに 1 個ごとの印 (PDC `iruurpg:uid`、乱数) を持つので、重ならない (1.20.4 には、アイテムごとの最大スタック数がないため)。素材は印なしで、今までどおり重なる。印は、指紋 (`createUnstamped`) に入らない。作り直しても、元の印を残す。
- いくつかをまとめて渡す所 (マーケット・返却箱・ダンジョンの報酬・モブのドロップ・クエストの報酬) は、`UniqueItems.pieces` で、1 個ずつ新しい印で渡す。
- **既存のアイテムの移行**: config `item-migration.mode` (off / dry-run / apply)。モードが変わると版が上がる (全員をもう一度見る)。
  - `dry-run`: 何も変えない (いつもの作り直しも)。印を付ける数・分けるスタックの数・作り直す数を、`item-migration-report.txt` に書く。マーケットと倉庫は切り替えたとき、プレイヤーはログインしたとき (オフラインの人の持ち物は、プラグインから読めないため)。
  - `apply`: 印の無い武器・防具に印を付け、2 個以上のスタックを 1 個ずつに分ける (同じ入れ物の空き → (プレイヤーなら) エンダーチェスト → フリマの受け取り箱 (`/market` で受け取る。地面には落とさない))。置いた入れ物で、空きが足りなければ、そのまま残す (ログ)。
    - 変える前に、プレイヤーのインベントリとエンダーチェストを `backups/item-migration/<日時>/<uuid>-<時刻>.yml` に保存する。マーケット・倉庫のファイルは、切り替えたときに、まとめて写す。保存できなければ、移行しない。
    - apply の間は、ログインのたびに見直す (マーケット・倉庫から出したスタックも、次のログインで分かれる)。
  - `/itemmigration status`、`/itemmigration restore <player> [フォルダ]` (オンラインのプレイヤーを、バックアップに戻す)。
- テスト: `ItemPatcherTest` に、重ならないこと・移行の印と分け方 (クラフトの強化を残す)・作り直しで印を残すこと。
