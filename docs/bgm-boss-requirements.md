# ボス BGM の依頼のまとめと作り方 (t283 で更新)

nekorozv の依頼を時系列で並べ直した。ボス曲を作る・直すときは、この文書を先に読む (規則の本体は [bgm-rules.md](bgm-rules.md)、型と時間表は「ボスBGM用・単調さを回避する楽曲構成設計書」、BPM は「BPM 設計ガイド」、楽器と進行は「BGM制作ガイド」)。

## 依頼の流れ (何を言われ、何を直してきたか)

| 依頼 | ユーザーの言葉の要点 | そのとき分かったこと |
|---|---|---|
| t269 | 作り直した曲が遅い。全体に少し速く | テンポは「1 拍が何ティックか」で決まる。BPM を上げる |
| t270 | 速さではなく、重さと凄みがない。フィールドや街の曲に聞こえる | きれいに作ると (高いハープ、静かなアルペジオ、きらめき、小さい低音とドラム) ボスに聞こえない。低く、重く、大きく、早く |
| t271 | 暗いだけではボスではない。フレーズの終わりが下がる、テンポが遅い、旋律が遅い。300 BPM の「ドライブ」版はずっと良い。ブルードマザー (Boss006) は良い。題名は気にしない。どれも「強い敵」に聞こえるように | ボスらしさ = **押し**: 速さ、同じ形を 1 段ずつ上げる上昇、終わりを下げずに上へ残す、ブロックの前のスネアのロール、全員で鳴らす「決め」 |

## t283 で分かったこと

1. **完全な無音がある** (`bossness.py` の `gap`): t281 の曲は、ブレイクの 1 小節や導入で、音が 1.6〜3.0 秒まったく鳴らない。ベースの途切れ (`nobass`) は最長 4.8 秒。ゲームの中では「サーバーが止まった」ように聞こえる。→ **音が 0.4 秒以上途切れない。ベースは 1.2 秒以上途切れない。ブレイクでも、ベース (やディジュリドゥ) の低い持続音は残し、ドラムと旋律だけを止める。曲頭の 0 ティック目から音が鳴る。ループのつなぎ目 (終わり → 64 ティック目) でも同じ。**
2. **拍がずれて鳴っていた** (エンジン、PR #484): t276 以降の曲は 1 秒 8.33 / 8.67 / 11 / 12 ティックで、曲ティックがサーバーの tick (50 ms) に乗らない。以前は音を「次の tick の頭」で鳴らしたので、16 分音符が 50 ms と 100 ms の交互に丸められ、最大 33〜50 ms ずれた。好評だった曲 (t271 の 300 BPM、200 BPM のブルードマザー) は 1 秒 20 ティックでずれがなかった。→ エンジンは音をその音の時刻ちょうどで送るように直した。曲を作る側は、**できるだけ 1 秒 20 / 10 / 6.67 / 5 ティック (サーバーの tick に乗る速さ) を選ぶ**。型 1 は 150 BPM = 1 秒 10 ティックで 16 分がちょうど 100 ms。
3. **音が多すぎた** (`bossness.py` の `peak`): 最密の 1 秒が 44〜48 音の曲があり、上限 45 を超えて、いちばん小さい音から送られていなかった (リズムの穴になる)。クライアントも同時に鳴らせる音に限りがあり、ボス戦では敵・技の音も鳴る。→ **1 秒に 40 音以下を目標にする。上限 (45) の世話にならない。** 聞こえない重ね (エコー、同じ音の重ね、小さい 16 分のハット) は書かない。
4. **持続音の打ち直しが遅い**: ノートブロックの音はすぐ消える。長音は 0.35 秒以内に、元の強さの 7 割以上で打ち直す (8.33 ティック/秒なら 3 ティックごと)。間があくと「ぶつ切り」に聞こえる。

## ボスらしさ (すべて必要)

- **押し** (t270/t271/t279): 大きく (旋律 78 以上、山場 85 以上)、低く (旋律の平均音高 68 以下、低音 42 以下)、最初の小節から (低音・ディジュリドゥ・キックは A の 1 小節目から大きい)。1〜2 小節の形を 1 段ずつ上げて繰り返す。フレーズの終わりは上へ残す。ブロックの前にスネアのロール、ブロックの頭と 4〜8 小節ごとに「決め」(6 音以上が同時)。光り物 (ベル・チャイム・柔らかいアルペジオ) はブレイクの 1 音だけ。
- **途切れない**: 上の 1 と 3 と 4。
- **型とクラス色** (t272/t277): 題名のモチーフ、6 分類の色、設計書の型 (導入 / A / B / ブレイク / サビ + モード反転 / 終盤) と BPM 梯子 (4 分 → 8 分 → 16 分の 2 連打・3 連符 → サビの 16 分マシンガンと長音の旋律)。
- **曲ごとの個性**: 主題 (3〜5 音)、調、リズムの形、楽器が曲ごとに違う。同じ曲の音量違いにならない。
- ボス 1 つの 2 曲 (フェーズ 1/2) は 1 つの曲: 同じ長さ・秒間ティック数・ループ位置 (64)、フェーズ 2 は強まった版。

## 確認の道具

```
python3 tools/bgm/bossness.py --table src/main/resources/bgm/<曲>.nbs    # 基準を外れると ! と終了コード 1
python3 tools/bgm/check_song.py src/main/resources/bgm/<曲>.nbs          # 同梱曲の規則
```
`bossness.py` の基準: lead ≥ 78、bass ≥ 55、drums ≥ 55、pitch ≤ 68、low ≤ 42、hits ≥ 80/分、kick ≥ 3.0/秒、**gap ≤ 0.40 秒、nobass ≤ 1.2 秒、peak ≤ 40 音/秒** (最後の 3 つは t283 で追加)。数値は「弱くない」ことしか言えない。聴いての確認はまだ。

## t290: ガイドの中身を測る (`guidecheck.py`)

| 依頼 | ユーザーの言葉の要点 | そのとき分かったこと |
|---|---|---|
| t290 | 今のボス BGM が最新のガイドを含められていない。boss2〜10 の構想・コードをリセットして 1 から作り直し | `bossness.py` は「押し・途切れ」だけを測っていた。設計書 (型の時間表、30〜45 秒に 1 回、ベースのルート固定は 20 秒まで) と BPM ガイド (4 分 → 8 分 → 16 分、サビは長音の旋律) の中身は未計測で、t283 の曲の多くが不合格だった |

```
python3 tools/bgm/guidecheck.py [--events] src/main/resources/bgm/<曲>.nbs    # ガイドの項目ごとに ok / !! 、--events で検出した時間線
```
ボス曲を作る・直すときは、`bossness.py` と `guidecheck.py` と `check_song.py` の **3 つとも** 通す。型はファイル名で決まる (`guidecheck.py` の `TYPES`)。項目の読み方は同ファイルの説明と `docs/bgm-songs.md` の t290 の節。
