# 画面効果 (screenfx/、t125〜)

クライアントのシェーダーで描く、画面全体の効果。色収差 (chromatic aberration、t129)、衝撃 (impact、t130: クリティカルのヒットストップの代わり。t133 から波紋)、止める (freeze、t134: その瞬間の画面から、だんだん実際の画面へ戻す)。ブルーム (t125) と暗くする (t126) は、依頼者の指示で t129 に消した。

## 使い方 (管理者)
- `/screenfx chromatic [強さ] [秒] [対象]`: 出す。赤は画面の中心から外へ、青は内へずれる。ずれは中心からの距離に比例し、強さ 100 で距離の 1.2 % (1920×1080 の左右の端で 11 ピクセル)。強さは 1〜255。秒を省くか 0 にすると、消すまで続く。対象はプレイヤー名かセレクター (`@a` など)。省くと自分。
- `/screenfx impact [強さ] [対象]`: 衝撃。ワールドの位置を画面に写した所から、波紋 (輪) が広がって消える。輪の上のピクセルを中心寄りから取る (輪の真ん中で最大、輪の端で 0。断面は 0..1..0 の三角を smoothstep でなめらかにしたもの)。輪は画面の高さの 60 % まで広がり、輪の幅は片側 8 %、ずらす量は始めに 3 % で、時間とともに (1 − 進み)² で弱まる。時間はクライアントの時間で、はじめは 0.25 倍の速さ、6 tick かけて 1 倍に戻る (全体で約 12 tick = 0.6 秒)。強さは 16 段階 (100 = 8 段目)。コマンドでは目の前 4 ブロックが中心。
- `/screenfx freeze [強さ] [対象]`: 止める。その瞬間の画面を持っておき、実際の画面へだんだん戻す。持っておいた画面の割合は exp(−4 S(t)) (S は smoothstep の積分を 0〜1 にしたもの。終わりで 0 にそろえる)。長さは強さ 100 で 6 tick (段階に比例)。割合はクライアントの時間 (始まった tick からの経過) だけで決まるので、フレームレートに関係なく同じ (30〜240 fps で確認)。
- **クリティカル**: 攻撃が当たってクリティカルだったとき、攻撃した人にだけ、当たった所 (相手の体の真ん中) から impact を出し (強さ 1: t134)、freeze も出す (`screen-effects.critical`: enabled、strength、freeze、freeze-strength)。何度も当たると、前のを動かして始め直す。
- `/screenfx chromatic off [対象]`: 消す。`/screenfx off [対象]`: その人の効果を全部消す。
- `/screenfx status [対象]`: いま何が出ているか。`/screenfx list`: 効果の一覧。
- プログラムからは `ScreenEffects#show(player, Effect.CHROMATIC, 強さ, tick)`、位置のある効果は `showAt(player, Effect.IMPACT, 位置, 強さ)`、一度だけの効果は `showTimed(player, Effect.FREEZE, 強さ)`、`hide` / `hideAll`。
- 見えるのは、サーバーのリソースパック (`iruumark.zip`) を入れている人だけ。シェーダーパック (Iris・OptiFine) を使っている人には出ない (バニラの描画が置き換わるため)。
- 目印は、シェーダー入りのパックを読み込めた人にだけ送る (t128)。クライアントは、パックごとに結果 (読み込めた・断った・ダウンロードできない・読み込みに失敗した) をサーバーに知らせる。断った・失敗した人には送らず、効果は覚えておいて、読み込めたら送る。読み込みに失敗した (FAILED_RELOAD) ときは、サーバーのログに警告を出す (シェーダーがその人のクライアントでコンパイルできなかったかもしれない)。
- Iris・OptiFine のシェーダーパックを使っているかは、サーバーからは分からない。それらの API はクライアントの中でしか呼べず、サーバーに何も知らせないため。そういう人に目印を送っても、大きさ 0 なので何も見えない (害はない)。`/screenfx status` で、パックの結果とクライアントの種類 (vanilla・fabric・forge など) が見られる。

## しくみ
サーバーは、クライアントでシェーダーを直接は動かせない。パックに入れたシェーダーが「見つけたら効果を出す」印 (マーカー) を、パケットでその人にだけ見せる。

1. **マーカー**: アイテムディスプレイ。発光の色は `(177, 番号 + 16 × 段階, 値)`。値は、色収差では強さ、時間のある効果 (impact) では始まった tick (ワールドのゲーム時刻 mod 240)。`setVisibleByDefault(false)` と `showEntity` で、その人にだけ送る。大きさ 0 なので、世界には何も描かれない。発光していて、発光の色が `(177, 効果の番号, 強さ)` (効果の番号は色収差が 1)。大きさ (width/height) が 0 のディスプレイは画面外でも描画対象になるので、近くにあればよい (5 tick ごとに、8 ブロック以上離れたら連れてくる。別のワールドでは作り直す)。保存されない。
2. **コアシェーダー** `core/rendertype_outline` (発光の輪郭を描くもの) を置き換える。マーカーの色の頂点だけ、本当の位置ではなく、輪郭の絵の左下の 4×4 ピクセル (x = 4 ×(番号 − 1)) に描く。下の 2 行の左 2 列は発光の色、下の 2 行の右 2 列は、始まった tick からの経過 (コアシェーダーの `GameTime` から。tick の端数つき、×256 の 16 ビット)、上の 2 行は、ディスプレイの本当の位置を画面に写した所 (`ProjMat * ModelViewMat * Position` → NDC。x と y を 12 ビットずつ、色の 24 ビットに入れる。−2〜2 を 0〜4094、カメラの後ろは 4095)。位置のある効果 (impact) は、ディスプレイをその位置に置く。
3. **ポストチェーン** `post/entity_outline.json` を置き換える。発光しているものが 1 つでも描かれると、ゲームはこのチェーンを毎フレーム流す。
   - はじめに、左下のマーカーを、8×3 の小さな絵 (`iruu_fx_state`) に読み取る。(番号 − 1, 0) = マーカーの色、(番号 − 1, 1) = 位置、(番号 − 1, 2) = 経過 tick。
   - freeze: `iruu_fx_hold` が、効果がないときはゲームの画面を、freeze の最初のフレームでその瞬間の画面を取り、終わるまでそれを持ち続ける (`iruu_hold`、`iruu_fx_copy` で次のフレームへ)。「前のフレームも同じ freeze だったか」は、`iruu_fx_memo` が 1×1 の絵に前のフレームの経過 tick を残して判断する (チェーンが止まっていた後の古い絵を使わないため)。
   - マーカーを消してから、ゲームと同じ輪郭を描く (マーカーが無いときの結果は、ゲームの輪郭と同じ。オフスクリーンの検証で差 0)。
   - 最後に、色収差と輪郭を 1 枚の絵 (`final`) にまとめる。ゲームは、フレームの最後 (手・水・パーティクルのあと、GUI の前) にこの絵を画面に重ねる。
   - ゲームの画面 (`minecraft:main`) には書けない (書くと途中で深度が消える) ので、効果は「重ねるとゲームの画面が効果をかけた画面になる」層として描く。各ピクセルを、別の場所から取る: impact は中心へ近づけた場所 (ふくらむ)、色収差は、そこから赤は外へ・青は内へずらした場所。その層の不透明度は、それができる一番小さい値 (色が変わらないところは 0 なので、触るのは物の縁だけ)。
4. 他の発光 (敵の Glowing、分身、スポナー探し) は、今までどおりの輪郭になる。マーカーの赤 177 は、チームの色 16 色のどれとも違う。

## 制限
- 効果のもとになるのは、不透明な世界 (地形・エンティティ・空) だけ。水・半透明のブロック・パーティクル・雲・天気・手は、チェーンのあとで描かれるので、それ自体はずれない。また、それらの後ろにある物の縁では、層がそれらの上に少し重なる (強さが大きいほど、impact は中心の近くほど目立つ)。
- 時間で動く効果 (impact) は、クライアントの時間で動く (t133)。サーバーは始まった tick を一度送るだけで、クライアントのゲーム時刻 (`GameTime`、サーバーと 1 秒ごとに合わせられる) から経過を出すので、フレームレートに関係なくなめらか。240 は 24000 を割り切るので、ゲーム時刻の折り返しをまたいでも数えられる。クライアントの時刻が少し遅れていると、経過が 240 近くになるので、200 より大きいときは「まだ始まっていない」として何もしない。
- 左下の 4×4 ピクセルに、ほかの発光の輪郭がちょうど重なったフレームは、効果が消えることがある (2 か所を読んでいるので、まれ)。
- `screen-effects.enabled: false` にすると、パックにシェーダーを入れず、`/screenfx` も使えない (起動時に読む)。

## 効果を足すとき
- `ScreenEffects.Effect` に番号 2〜8 で足す。マーカーはその番号の場所 (左下の x = 4 ×(番号 − 1)) に描かれる。
- `post/entity_outline.json` にパスを足し、`StateSampler` (= `iruu_fx_state`) の (番号 − 1, 0) を読む (a が 1 ならマーカーあり、b が強さ)。
- 新しいファイルは `markpack/ScreenShaders.FILES` に足す (全部そろわないと、パックに入れない)。
- 新しいパスの頂点シェーダーは `iruu_fx` を使い、program の JSON の uniforms に `OutSize` を入れる。ゲームは、どのパスにも画面の大きさの `ProjMat` を渡すので、`ProjMat` で四角を作ると、画面より小さい出力先には左下の一部しか描かれない (t127)。
- 変えたら、オフスクリーンの検証 (ワークスペースの `design/screenfx-shadertest.swift`) で確かめる。
