# 画面効果 (screenfx/、t125〜)

クライアントのシェーダーで描く、画面全体の効果。今は色収差 (chromatic aberration、t129)。ブルーム (t125) と暗くする (t126) は、依頼者の指示で t129 に消した。

## 使い方 (管理者)
- `/screenfx chromatic [強さ] [秒] [対象]`: 出す。赤は画面の中心から外へ、青は内へずれる。ずれは中心からの距離に比例し、強さ 100 で距離の 1.2 % (1920×1080 の左右の端で 11 ピクセル)。強さは 1〜255。秒を省くか 0 にすると、消すまで続く。対象はプレイヤー名かセレクター (`@a` など)。省くと自分。
- `/screenfx chromatic off [対象]`: 消す。`/screenfx off [対象]`: その人の効果を全部消す。
- `/screenfx status [対象]`: いま何が出ているか。`/screenfx list`: 効果の一覧。
- プログラムからは `ScreenEffects#show(player, Effect.CHROMATIC, 強さ, tick)` / `hide` / `hideAll`。
- 見えるのは、サーバーのリソースパック (`iruumark.zip`) を入れている人だけ。シェーダーパック (Iris・OptiFine) を使っている人には出ない (バニラの描画が置き換わるため)。
- 目印は、シェーダー入りのパックを読み込めた人にだけ送る (t128)。クライアントは、パックごとに結果 (読み込めた・断った・ダウンロードできない・読み込みに失敗した) をサーバーに知らせる。断った・失敗した人には送らず、効果は覚えておいて、読み込めたら送る。読み込みに失敗した (FAILED_RELOAD) ときは、サーバーのログに警告を出す (シェーダーがその人のクライアントでコンパイルできなかったかもしれない)。
- Iris・OptiFine のシェーダーパックを使っているかは、サーバーからは分からない。それらの API はクライアントの中でしか呼べず、サーバーに何も知らせないため。そういう人に目印を送っても、大きさ 0 なので何も見えない (害はない)。`/screenfx status` で、パックの結果とクライアントの種類 (vanilla・fabric・forge など) が見られる。

## しくみ
サーバーは、クライアントでシェーダーを直接は動かせない。パックに入れたシェーダーが「見つけたら効果を出す」印 (マーカー) を、パケットでその人にだけ見せる。

1. **マーカー**: アイテムディスプレイ。`setVisibleByDefault(false)` と `showEntity` で、その人にだけ送る。大きさ 0 なので、世界には何も描かれない。発光していて、発光の色が `(177, 効果の番号, 強さ)` (効果の番号は色収差が 1)。大きさ (width/height) が 0 のディスプレイは画面外でも描画対象になるので、近くにあればよい (5 tick ごとに、8 ブロック以上離れたら連れてくる。別のワールドでは作り直す)。保存されない。
2. **コアシェーダー** `core/rendertype_outline` (発光の輪郭を描くもの) を置き換える。マーカーの色の頂点だけ、本当の位置ではなく、輪郭の絵の左下の 4×4 ピクセル (x = 4 ×(番号 − 1)) に描く。
3. **ポストチェーン** `post/entity_outline.json` を置き換える。発光しているものが 1 つでも描かれると、ゲームはこのチェーンを毎フレーム流す。
   - はじめに、左下のマーカーを、8×1 の小さな絵 (`iruu_fx_state`、番号 − 1 のピクセル = マーカーの色) に読み取る。
   - マーカーを消してから、ゲームと同じ輪郭を描く (マーカーが無いときの結果は、ゲームの輪郭と同じ。オフスクリーンの検証で差 0)。
   - 最後に、色収差と輪郭を 1 枚の絵 (`final`) にまとめる。ゲームは、フレームの最後 (手・水・パーティクルのあと、GUI の前) にこの絵を画面に重ねる。
   - ゲームの画面 (`minecraft:main`) には書けない (書くと途中で深度が消える) ので、色収差は「重ねるとゲームの画面が色収差の画面になる」層として描く: 赤はずれた先の赤、青は逆向きにずれた先の青、緑はそのまま。その層の不透明度は、それができる一番小さい値 (色が変わらないところは 0 なので、触るのは物の縁だけ)。
4. 他の発光 (敵の Glowing、分身、スポナー探し) は、今までどおりの輪郭になる。マーカーの赤 177 は、チームの色 16 色のどれとも違う。

## 制限
- 色収差のもとになるのは、不透明な世界 (地形・エンティティ・空) だけ。水・半透明のブロック・パーティクル・雲・天気・手は、チェーンのあとで描かれるので、それ自体はずれない。また、それらの後ろにある物の縁では、層がそれらの上に少し重なる (強さが大きいほど目立つ)。
- 左下の 4×4 ピクセルに、ほかの発光の輪郭がちょうど重なったフレームは、効果が消えることがある (2 か所を読んでいるので、まれ)。
- `screen-effects.enabled: false` にすると、パックにシェーダーを入れず、`/screenfx` も使えない (起動時に読む)。

## 効果を足すとき
- `ScreenEffects.Effect` に番号 2〜8 で足す。マーカーはその番号の場所 (左下の x = 4 ×(番号 − 1)) に描かれる。
- `post/entity_outline.json` にパスを足し、`StateSampler` (= `iruu_fx_state`) の (番号 − 1, 0) を読む (a が 1 ならマーカーあり、b が強さ)。
- 新しいファイルは `markpack/ScreenShaders.FILES` に足す (全部そろわないと、パックに入れない)。
- 新しいパスの頂点シェーダーは `iruu_fx` を使い、program の JSON の uniforms に `OutSize` を入れる。ゲームは、どのパスにも画面の大きさの `ProjMat` を渡すので、`ProjMat` で四角を作ると、画面より小さい出力先には左下の一部しか描かれない (t127)。
- 変えたら、オフスクリーンの検証 (ワークスペースの `design/screenfx-shadertest.swift`) で確かめる。
